# Web-ларёк. Бэкенд

REST API для интернет-магазина «Web-ларёк» на Express, MongoDB и TypeScript.

Сервер отдаёт каталог товаров и принимает заказы. Кроме того, в нём есть регистрация и вход по JWT с refresh-токенами, загрузка изображений и управление товарами из админки.

В репозитории есть фронтенд на React (`frontend/`), с ним удобно проверять бэкенд вручную.

## Стек

- **Node.js**, **Express 4**, **TypeScript**
- **MongoDB** и **Mongoose**
- **celebrate / Joi** для валидации запросов
- **jsonwebtoken**, **bcryptjs**, **cookie-parser** для авторизации
- **multer** для загрузки файлов
- **winston / express-winston** для логов
- **ESLint** (airbnb-base) для линтинга

## Возможности

- **Каталог товаров:** список, создание, редактирование и удаление.
- **Оформление заказа** с проверкой:
  - товары существуют и продаются;
  - сумма заказа совпадает с ценами товаров.
- **Регистрация и вход:**
  - пароль хранится в виде хеша;
  - access-токен живёт 10 минут, refresh-токен 7 дней и хранится в httpOnly-cookie;
  - при обновлении refresh-токен заменяется новым.
- **Загрузка изображений:**
  - файл сначала попадает во временную папку и переносится в постоянную при сохранении товара;
  - при удалении товара или замене картинки старый файл удаляется.
- **Валидация** всех входящих данных до контроллера (celebrate) и на уровне схем Mongoose.
- **Централизованная обработка ошибок:** все ошибки возвращаются в едином формате `{ "message": "..." }`.
- **Логи:** запросы пишутся в `request.log`, ошибки в `error.log`.

## Запуск

### Локально

Нужны Node.js 18+ и MongoDB, запущенная на `127.0.0.1:27017`.

```bash
cd backend
cp .env.example .env   # при необходимости поменять значения
npm install
npm run dev            # сервер с hot reload на http://localhost:3000
```

Фронтенд для проверки запускается во втором терминале:

```bash
cd frontend
cp .env.example .env
npm install
npm run dev            # http://localhost:5173
```

### В Docker

1. В `backend/.env` указать адрес базы из контейнера: `DB_ADDRESS=mongodb://root:example@mongo:27017/`.
2. В `frontend/.env` указать `VITE_API_ORIGIN=http://localhost/api`.
3. Запустить:

```bash
docker compose up -d
```

Приложение будет доступно на http://localhost, API — на http://localhost/api.

### Команды

Все команды выполняются из папки `backend`.

| Команда         | Что делает                                                         |
| --------------- | ------------------------------------------------------------------ |
| `npm run start` | запускает сервер через ts-node                                     |
| `npm run dev`   | запускает сервер с перезапуском при изменении файлов (ts-node-dev) |
| `npm run build` | собирает проект в `dist`                                           |
| `npm run lint`  | проверяет код ESLint                                               |

## API

Роуты с отметкой * требуют заголовок `Authorization: Bearer <access-токен>`.

| Метод и роут                    | Описание                                                                      | Ответ                                                        | Ошибки                  |
| ------------------------------- | ----------------------------------------------------------------------------- | ------------------------------------------------------------ | ----------------------- |
| `GET /product`                  | все товары                                                                    | `200 { items, total }`                                       | 500                     |
| `POST /product` *              | создать товар                                                                 | `201` товар                                                  | 400, 401, 409, 500      |
| `PATCH /product/:productId` *  | обновить товар, все поля необязательны                                        | `200` товар                                                  | 400, 401, 404, 409, 500 |
| `DELETE /product/:productId` * | удалить товар                                                                 | `200` удалённый товар                                        | 400, 401, 404, 500      |
| `POST /order`                   | оформить заказ                                                                | `200 { id, total }`                                          | 400, 500                |
| `POST /auth/register`           | регистрация                                                                   | `201 { user, success, accessToken }` и cookie `refreshToken` | 400, 409, 500           |
| `POST /auth/login`              | вход                                                                          | `200 { user, success, accessToken }` и cookie `refreshToken` | 400, 401, 500           |
| `GET /auth/token`               | новая пара токенов по cookie `refreshToken`                                   | `200 { user, success, accessToken }` и новая cookie          | 401, 404, 500           |
| `GET /auth/logout`              | выход по cookie `refreshToken`                                                | `200 { success }`, cookie удаляется                          | 400, 401, 404, 500      |
| `GET /auth/user` *             | текущий пользователь                                                          | `200 { user, success }`                                      | 401, 404, 500           |
| `POST /upload` *               | загрузить изображение во временную папку (`multipart/form-data`, поле `file`) | `201 { fileName, originalName }`                             | 400, 401, 500           |

Любой другой роут возвращает `404`.

Ошибки приходят в формате:

```json
{ "message": "Поле \"title\" должно быть заполнено" }
```

Изображения раздаются статически: `GET /images/<имя файла>`.

### Пример товара

```json
{
  "_id": "66601a8c57ecac94459696d6",
  "title": "Мамка-таймер",
  "image": {
    "fileName": "/images/Asterisk_2.png",
    "originalName": "Asterisk_2.png"
  },
  "category": "софт-скил",
  "description": "Будет стоять над душой и не давать прокрастинировать.",
  "price": null
}
```

Товар с `price: null` не продаётся, и заказ с ним сервер отклонит.

### Пример заказа

```json
{
  "payment": "card",
  "email": "admin@ya.ru",
  "phone": "+79999999999",
  "address": "Москва, ул. Пушкина, 1",
  "total": 2200,
  "items": ["66601a8c57ecac94459696d6", "66601ac957ecac94459696e8"]
}
```

`payment` принимает значения `card` или `online`. `total` должен совпадать с суммой цен товаров из `items`.

### Загрузка изображения и создание товара

1. `POST /upload` с файлом в поле `file`. Разрешены png, jpg, jpeg, gif и svg размером до 10 МБ. В ответе вернётся `{ "fileName": "/images/<uuid>.png", "originalName": "photo.png" }`.
2. `POST /product`, где в поле `image` передаётся объект из ответа на загрузку. При сохранении файл переносится из временной папки в `src/public/images`.

## Структура

```
backend/src
├── app.ts              # точка входа: middleware, роуты, подключение к БД
├── config.ts           # параметры из .env
├── controllers/        # обработчики запросов: товары, заказ, авторизация, загрузка
├── errors/             # классы ошибок 400, 401, 404, 409
├── middlewares/        # авторизация, валидация, загрузка файлов, логи, обработчик ошибок
├── models/             # схемы Mongoose: товар и пользователь
├── routes/             # роуты
├── utils/              # работа с файлами изображений
└── public/images/      # изображения товаров
```
